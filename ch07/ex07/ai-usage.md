## プロンプトと得られたヒントの概要

### 1. O(n^2) でない、実装しやすいソート

> 問題7.7でソートについて勉強している。初心者が実装しやすいソートで時間がO(n^2)じゃないやつってある？

得られたヒント:

- バブル / 選択 / マージ / クイック / ヒープソートの計算量と書きやすさの比較表を示され、常に O(n log n) で説明しやすいマージソートを勧められた。
- 「半分に分ける → それぞれを再帰的にソート → ソート済みの 2 つをマージ → 要素 1 個以下なら終了」という流れ。
- まず「ソート済みの配列 2 つを 1 つにする」関数 (merge) から作ると取り組みやすい。

### 2. マージソートのイメージ

> マージソートの考え方で2つに分けてそれぞれの値を比較するはわかるけど、比較対象が[5,4,3,2,1],[2,1]とか例えば偏っていた場合とかについてもあまりピンとこないし、マージするっているのもピンとこない。

得られた回答:

- ソートされていない配列同士を比べることはない。要素が 1 個になるまで分け続け (1 個の配列はソート済み)、ソート済み同士をマージしながら戻っていく。`[5, 4, 3, 2, 1]` を分ける木と、マージで戻る過程の図で説明を受けた。
- マージは「小さい順に重ねたトランプの山 2 つから、一番上の小さい方を取っていく」イメージ。各山はソート済みなので、一番上同士だけを比べればよい。
- 分け方は値ではなく位置で半分にするので、偏りは生じない。

### 3. 関数の分け方と再帰

> マージ関数は2つのソート済みの配列を引数として比較して1つのものにしてretrunで、配列を2つに分けてそれぞれをソートする関数も別に書くイメージ？
>
> while(要素が1以下になるまで) mergeSort(右半分) mergeSort(左半分) merge(ここ何？) return みたいな感じ？

得られたヒント:

- 関数は `merge` と `mergeSort` の 2 つ。「半分をソートする」部分は別の関数ではなく `mergeSort` 自身を呼ぶ (再帰)。
- 分け続ける繰り返しは再帰が担うので while は不要。終了条件は if で「要素が 1 個以下ならそのまま return」と書く。
- `merge` に渡すのは、左右それぞれの `mergeSort` の戻り値 (ソート済みの配列)。再帰呼び出しは「ちゃんとソートして返してくれる」と信じて書く。

### 4. 比較関数 `compare` の意味と、デフォルト引数にする理由

> compare = (lhs, rhs) => (lhs < rhs ? -1 : lhs > rhs ? +1 : 0) そもそもこれなんだ？なんで-1とか+1を返す？
>
> 「並べ方をソートの外から変えられるようにするため」ここがよくわからない
>
> オブジェクトの場合は.ageとかってつけなくてはいけないのでは？
>
> 再帰的に書くから、compareでデフォルトを設定した方が書きやすいってことかな？
>
> じゃあ、配列だけを渡してマージ関数書いても同じじゃないの？

得られた回答:

- デフォルト引数・アロー関数・三項演算子の入れ子の組み合わせ。戻り値は負なら `lhs` が前、正なら後ろ、0 なら同じ扱い (`Array.prototype.sort` と同じ約束)。前・後ろ・等しいの 3 通りを表すために数値を使う。
- 「2 つのうち先に並べる方を返す関数 `first`」の小さな例で、compare を引数にすると関数の中身を変えずに昇順・降順・`age` 順を切り替えられることを説明された (手順とルールを分ける)。
- デフォルトの compare は、数値・文字列を compare なしでソートしたいときの予備。オブジェクトの場合は呼ぶ側が `.age` などを使った compare を渡し、デフォルトは使われない。`<` / `>` で書くのは文字列も比べられるため (`"apple" - "banana"` は `NaN`)。
- デフォルトは再帰とは関係なく、利用者の手間を減らすためのもの。再帰や merge の呼び出しでは、受け取った `compare` をそのまま渡すだけ。渡し忘れるとデフォルトが黙って使われるので注意。
- 数値の昇順だけなら compare なしでも同じ結果になる。まず compare なしで書き、問題 7.4 のデータを並べようとして困ったら導入する進め方も提案された。

### 5. merge の書き方

> 「merge(a, b, compare) 繰り返し: ...」ここも難しい
>
> merge(arr1,arr2,compare)って書く場合、compare(arr1[i] ,arr2[j]) >0みたいな感じにできるの？
>
> マージ関数は2つの配列をそれぞれfor文でループさせるってことか？でも片方が空になるまではwhileするんだよね？
>
> whileが終わった後って、どっちが残っているかみたいなのをわざわざif文で書く必要ある？

得られたヒント:

- 先頭の位置をインデックス `i`, `j` で覚えておき、取った方だけ進める。`a = [4, 5]`, `b = [1, 2, 3]` を表で手で追った。
- `compare(arr1[i], arr2[j]) > 0` なら `arr2` 側を取る。0 のときは `arr1` 側を取ると同じ値の元の順番が保たれる (安定ソート)。
- for を 2 つ回すのではなく、while を 1 つ回して `i` か `j` の片方だけを進める。
- 使い切った方を `slice` すると空配列になるので、if で分けずに両方の残りをつなげてよい。

### 6. テストでの compare

> テストでcompareをとりあえず定義するときってcompare = (lhs, rhs) => ...;って書いてもいい？

得られた回答:

- 普通の変数として定義するなら `const` が必要 (ES モジュールでは付けないと `ReferenceError`)。
- デフォルトと同じ関数を渡すだけでは compare が使われているかを確かめられないので、降順や `age` 順など別の並べ方になる compare もテストするとよい。

### 7. 自分で書いたコードの不具合

> 関数書いたつもりだけどかけてなかった
>
> あれ、テスト間違えた？
>
> mergeSortうまくいかなかった

得られたヒント (自分で書いたコードに対する指摘):

- `return result.push(...)` は `push` の戻り値 (新しい長さ) を返している。MDN で `push` の返値を確認するよう促された。
- `...arr1` だと全要素を足してしまうので、`i` 番目から後ろだけを取る (`slice(i)`)。
- 降順の compare で昇順の配列を merge するテストは、merge の前提 (渡された compare の順にソート済み) を満たしていない。配列・compare・期待値の向きをそろえる。
- mergeSort で要素が減るのは分割部分が原因。`slice` の第 2 引数の位置の要素が結果に含まれるかを確かめるよう促された。

### 8. 時間計算量の説明

> 実装したアルゴリズムの入力の配列長 n に対する時間計算量を O-記法で説明しなさい。関数は完成したので後はどうやって説明するか…
>
> O-記法がそもそもよくわかってない
>
> pushの数 x mergeが呼ばれる回数 x 段の数ってこと？
>
> 「1 段あたりのコストは ___ になる」ここがイメージが難しい
>
> merge 1 回のコスト p + q 回 これって計算量に関わるの？

得られたヒント:

- O-記法は「n が増えたとき処理回数がどのペースで増えるか」を表す。定数倍や小さい項は無視する。ループ 1 つ = O(n)、入れ子 = O(n^2)、半分にし続ける = O(log n) の例と、n / n log n / n^2 の比較表で説明を受けた。
- 「merge 1 回のコスト → 1 段あたりのコスト → 段の数 → 全体」の 3 ステップで組み立てる。n = 8 の具体例で数えると考えやすい。
- merge の push は p × q ではなく p + q 回。`p + q - 1` は比較回数の最大値で、比較回数は min(p, q) 〜 p + q - 1 回。
- 「push 数 × merge の回数」は 1 段の中で掛ける。どの段でも全要素がちょうど 1 回ずつ push されるので、1 段あたりは n になる (1 つの要素を追う図、クラスの班分けのたとえ)。
- 最終的な式は「各段 n × 段数 log₂ n」。p + q は「各段 n」と言える根拠。
- 穴埋め形式の説明テンプレートを示され、自分で数えた結果を埋めて書くよう促された。

### 9. Markdown での書き方

> log2nってmarkdownで書き方あるっけ？
>
> n×ってかける？

得られた回答:

- `log₂ n`、`<sub>`、`$\log_2 n$`、``$`\log_2 n`$`` (問題文の README と同じ書き方) などがある。
- `×` は「かける」で変換するか、数式中で `\times`。O-記法では `O(n log n)` のように省略するのが一般的。
