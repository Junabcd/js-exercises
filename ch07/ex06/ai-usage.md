# AI 利用記録 (ch07/ex06)

- 日付: 2026-11-06
- 使用ツール: Claude Code (モデル: Claude Opus 5.5)
- 利用方針: 解答コードの生成は依頼せず、`sort` の比較関数でのオブジェクトの扱い方、複数条件での並べ替えの考え方、元の配列をコピーすべきかについてヒントを受けた。解答 (index.js) は自分で作成した。

## プロンプトと得られたヒントの概要

### 1. 比較関数でオブジェクトのプロパティを使えるか / 複数条件の書き方

> 問題7.6でsortをかけるが、(a,b) => b-aにする際に、a,bがobjectになるなら、b.mathのようにできるのか？
> あと、sortの中で並べ替えの条件を複数入れる方法って簡単に書けるのか？

得られたヒント:

- 比較関数には配列の要素がそのまま `a`, `b` として渡されるので、`b.math` のようにプロパティを使える。
- 比較関数は戻り値の符号だけを見る (負なら `a` が前、正なら `b` が前、`0` なら順序を変えない)。`b - a` が降順になるのはこのため。
- `0` は falsy なので、`第1条件の差 || 第2条件の差` と書けば「同点のときだけ次の条件で比べる」ことができる。条件が増えても `|| ...` を続ければよい (課題とは別のデータ `price` / `stock` で昇順の例を示された)。
- 「高い順」にするには引き算の向きをどうするか、`sort` が破壊的であることをどう扱うかを考えるよう促された。

### 2. コピーしてからソートすべきか

> ソートしてくださいとしか言われてないけど、一応コピーしてから処理した方がいいかな？

得られた回答:

- コピーしてからソートする方が無難。元の `data` を他の計算でも使う可能性があり、引数を書き換えない関数の方が使う側が驚かない。コピーは O(n) でソート (O(n log n)) より軽い。
- 元の並び順が不要な場合や、巨大な配列でメモリ・速度を優先したい場合は、そのままソートしてもよい。
- `[...data]` や `toSorted()` は浅いコピーで、中のオブジェクトは共有される。今回は中身を書き換えないので問題ない。
- `toSorted()` は ES2023 のメソッドで、環境によっては使えない場合がある。
