# AI 利用記録 (ch07/ex09)

- 日付: 2026-11-07
- 使用ツール: Claude Code (モデル: Claude Opus 5.5)
- 利用方針: 解答 (説明文) の作成は依頼せず、`"👨‍👨‍👧‍👧"[0]` が表示できなかった理由を調べる方法、コードユニット / コードポイント / 書記素の違い、サロゲートペアと ZWJ、`charCodeAt` / `codePointAt` / `slice` の動きについてヒントを受けた。解答 (index.js, index.md) は自分で作成する。

## プロンプトと得られたヒントの概要

### 1. `"👨‍👨‍👧‍👧"[0]` が表示できない

> console.log("👨‍👨‍👧‍👧"[0]) → � nodeでやってみたけど、表示できなかった。何か別の方法で見えるようにするべき？

得られたヒント:

- `�` (U+FFFD 置換文字) は「文字として成立していないので描画できない」ことを表す。別の表示方法を探すより、中身を数値で確認する方が課題に合っている。
- `s[0].length`、`s[0].charCodeAt(0).toString(16)`、`JSON.stringify(s[0])`、`s.length`、`s.codePointAt(0)`、`[...s]` を `"𠮷野家"` と `"👨‍👨‍👧‍👧"` で試すよう促された。
- 調べるキーワード: UTF-16、サロゲートペア (`d800`〜`dfff`)、ゼロ幅接合子 (`200d`)。

### 2. 結果の読み方

> 16進でコード値出たねってくらいの感想なんだけど…。

試した結果: `"𠮷野家"[0]` は `"\ud842"`、`length` は 4。`"👨‍👨‍👧‍👧"[0]` は `"\ud83d"`、`length` は 11。

得られたヒント:

- 見た目 3 文字なのに長さ 4、見た目 1 文字なのに長さ 11 になる。`length` や `[0]` は見た目の 1 文字を単位にしていない。
- `s[0]` / `s[1]` の `charCodeAt` と `codePointAt` を比べ、「UTF-16 サロゲートペア」を調べるよう促された。
- `[...s].map(...)` で 11 を「? × ? + ?」に分解してみるよう促された。
- コードユニット (`[i]`, `length`)、コードポイント (`[...s]`, `codePointAt`)、書記素 (`Intl.Segmenter`) の 3 つを区別してまとめるとよい。

### 3. 11 の内訳

> 16進数のコードを2つ（サロゲートペア）で4つ分なので、2x4で、その間に結合を入れるから+3ってこと？200dは1文字分の結合？

得られた回答:

- 11 = 2 × 4 + 3 で合っている。👨 / 👧 はそれぞれ 2 コードユニット、ZWJ (`200d`) は 1 コードユニット。
- ZWJ は前後の絵文字をつなげて 1 つとして表示させる、見えない文字。
- 👨 のコードポイントは 5 桁、`200d` は 4 桁。1 コードユニットは 16 ビット (最大 `ffff`) なので、それを超える文字をどう格納するかを考えると説明が良くなる。

### 4. `codePointAt` が表すもの

> codePointAtって何を表しているの？16bitで表せないものとかも判断できるってこと？

得られた回答:

- `charCodeAt(i)` は i 番目のコードユニット (16 ビット) をそのまま返す。`codePointAt(i)` は i 番目から読み、サロゲートペアの前半なら後半と組み合わせて本来のコードポイントを返す (`"👨"`: `d83d` + `dc68` → `1f468`)。
- 引数の位置はコードユニット単位のまま。`codePointAt(1)` だと後半だけが返る。文字単位で扱うなら `[...s]` や `for...of` を使う。
- コードユニット 11 / コードポイント 7 / 書記素 1 の比較表で整理した。

### 5. `codePointAt(0)` が `d83d` になった

> s.codePointAt(0).toString(16);がd83dになった

得られたヒント:

- `s` の中身が前半のサロゲート `\ud83d` だけになっている可能性がある。`s.length` と `JSON.stringify(s)` で確認する。
- 原因の候補: `s[0]` に対して呼んでいる。または、Windows のターミナルで絵文字を貼り付けたときに壊れている (`.js` ファイルで実行するか、`"\u{1F468}"` とエスケープで書く)。

### 6. 2 ユニット分を取り出す方法

> 2つ文字文で表示みたいな書き方できない？[0,1]みたいな

得られた回答:

- `s.slice(0, 2)` でコードユニット 2 つを取り出せる。終了位置を 1, 2, 3, 5 と増やすと、ペアがそろう様子や ZWJ でつながる様子が見える。
- `s[0,1]` はカンマ演算子で `s[1]` と同じになる。
- コードポイント単位の 0 番目は `[...s][0]`。

### 7. サロゲートペアでない文字との違い

> s.slice(0, 2); でサロゲートペアの場合は16bit超えるけど、これが、「あい」のようにサロゲートペアが必要ないものでやると結局16bit超えてしまう？
>
> これってサロゲートペア出なかった場合は1文字分しか結局取らないってこと？
>
> だから16bit超えてたらサロゲートだってわかるのか

得られた回答:

- 「16 ビットを超える」は、1 文字のコードポイントが `ffff` より大きいかどうかの話で、文字列全体のサイズの話ではない。`"あい".slice(0, 2)` は 2 文字、`"👨".slice(0, 2)` は 1 文字 (どちらも 16 ビット × 2)。
- `codePointAt(i)` は常に 1 コードポイント分だけ読む。2 ユニットを読むのはサロゲートペアの場合だけで、それ以外は `charCodeAt` と同じ値になる。
- `codePointAt` の結果が `0xffff` を超えれば、サロゲートペアで格納されていたと分かる。
- `codePointAt` 自身は、コードユニットの値が `d800`〜`dbff` (前半専用) / `dc00`〜`dfff` (後半専用) の予約領域にあるかで判別している。前半だけが単独で表示されると、相手がいないので `�` になる。
