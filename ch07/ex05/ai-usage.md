## プロンプトと得られたヒントの概要

### 1. 問題文の `users.sort(...)` の意味

> 問題7.5の例にあるconst sorted = users.sort((a, b) => a.name.localeCompare(b.name));ってなんの処理？

得られた回答:

- `users` を `name` の辞書順 (昇順) に並べ替える処理。
- `sort` の比較関数は、負の数なら `a` が前、正の数なら `b` が前、`0` なら順序を変えない。`localeCompare` は文字列を比べて負/0/正を返すので、そのまま比較関数に使える。
- `sort` は元の配列を書き換え、その同じ配列を返す (`sorted === users` は `true`)。そのため `users[0].name` が `fuga` になる。

### 2. React の NG 例で値は追加されないのか

> 実際に値は追加されないの？

得られた回答:

- `push` で配列に値は実際に追加される。ただし `setUsers` に同じ配列 (同じ参照) を渡すと、React は `Object.is` で比べて「変わっていない」と判断し、再レンダリングしないので画面が更新されない。
- 別の理由で再レンダリングが起きると急に表示される、という見つけにくいバグになりやすい。

### 3. `a = b` で非破壊になるか

> 非破壊的関数の考え方だけど、a = bみたいにして、aという配列を作って代入するやり方は正しいの？

得られたヒント:

- `a = b` でコピーされるのは参照だけで、`a` と `b` は同じ配列を指す。片方を変更するともう片方も変わる。
- 新しい配列を作る方法として、スプレッド構文 `[...配列]`、`slice()`、`Array.from()` を調べるよう促された。
- これらは浅いコピーで、中のオブジェクトは共有される。

### 4. 浅いコピーの「入れ物」と「中身」の違い

> 配列の場合は要素の削除とかだから中身が共有されないという特殊例？
>
> 入れ物を操作すると中身も変わるイメージだから、正直配列の要素も変わるような印象だけど…。入れ物を操作しても中身は同じっていうのがややこしい

得られた回答:

- 配列に限った話ではなく、浅いコピーは「入れ物は別、中のオブジェクトは共有」。オブジェクトの `{ ...obj }` でも同じ。
- 「要素が変わる」には、(A) `a[0]` に入っているものが別のものになる、(B) オブジェクトそのものが書き換わる、の 2 つの意味がある。push/pop/sort などは (A) だけで、(B) は起きない。
- プレイリスト (配列) と曲 (オブジェクト) のたとえで説明を受けた。

### 5. 浅いコピーで問題の要件を満たすか

> 各関数は返り値に変更後の新しい配列を返しなさい。ってあるけど、これって浅いコピーでも大丈夫なの？

得られた回答:

- 大丈夫。要件は「新しい配列を返す」「元の配列を変えない」の 2 点で、push/pop などは入れ物しか操作しないため。
- 標準の非破壊メソッド (`toSorted` など) や React の例も浅いコピー。

### 6. 非破壊版 `pop` の中で `pop` を使ってよいか

> 非破壊的関数popを作る際、その中でpopって使っていいの？それとも別の方法で要素を削除するべき？

得られたヒント:

- コピーに対して使うなら問題ない (コピーしてから破壊的メソッドを使うのは定番の考え方)。
- `pop` などの戻り値は変更後の配列ではないので、`return コピー.pop()` にしないよう注意。
- `slice` のような非破壊メソッドを使う方法もある。

### 7. テストの書き方

> テストでpopにseqを入れてもseqは変わらないってどういう風に書くの？
>
> expectでseqをいじっても、seqには影響しない？
>
> expect(pop(seq)).toEqual([1, 2, 3, 4]);の後にわざわざpop(seq)を呼ぶ必要はなく、seqが変わったか確かめればいいってこと？
>
> ===で中身までは変えられていないようなテストが書けるの？ヒント
>
> 返り値と元の配列が === で別物になっているかみたいなのってnot.tobeってこと？

得られたヒント:

- 関数を呼んだあと、`seq` が呼ぶ前と同じ中身かを `toEqual` で確かめる (`toSorted` / `sort` を例に説明を受けた)。比較相手は配列リテラルで書く。`expect(seq).toEqual(seq)` や `const before = seq` との比較では意味がない。
- `expect` や `toEqual` は値を読むだけで `seq` を変えない。ただし `expect(...)` のカッコ内の式は実行される。
- 返り値を変数に入れて、関数を 1 回だけ呼んでから確かめるとすっきりする。
- `===` (`toBe`) は同じものかしか見ないので、中身の書き換えは検出できない。中身の確認には `toEqual` を使う。
- `not.toBe` で返り値と元の配列が別の入れ物であることを確かめられる。`toBe` は内部で `Object.is` を使う (`NaN` と `±0` 以外は `===` と同じ)。

### 8. `push` で複数の値を受け取る

> pushに関しては2つ目の引数に...elemのようにして複数入れられるようにしたい。引数がなかった場合はどうすればいいんだろう？""とかにすると空文字がはいる？
>
> pushでelemsってやると、すんなりいく？それとも工夫が必要？
>
> 配列として引数になるからスプレッド構文で代入すればそれぞれの要素として入る？

得られたヒント:

- 残余引数は引数がなくても空の配列 `[]` になるので、特別な扱いは不要。残余引数にデフォルト値は付けられない。`""` を入れると空文字が追加されてしまう。
- `push(elems)` だと配列 1 個が要素として追加されて入れ子になる。関数呼び出しでのスプレッド構文を調べるよう促された。
- `...` は、関数定義の引数では「まとめる」(残余引数)、関数呼び出しでは「広げる」(スプレッド構文) と働きが逆。

### 9. 何も追加しなかった場合に `[]` が追加される

> 何も追加しなかった場合[]が追加された

得られたヒント (自分で書いたコードに対する指摘):

- `copyArr.push([...elems])` の `[ ]` で新しい配列を 1 個作って渡しているのが原因。`...elems` と `[...elems]` の違いを見比べるよう促された。
- テストの `push(seq, 7, 8, 9)` の期待値に `6` が入っているが、`push` が非破壊なら正しいか見直すよう指摘された。
- `seq` が変わっていないかを確認するテストを、`pop` と `push` に追加するとよい。

### 10. `sort` の比較関数

> sort(seq, (a, b) => b - a) これって引数に関数を渡してるとみなす？

得られた回答:

- 第 2 引数に関数 (コールバック関数) を渡している。関数も値として変数に入れたり引数に渡したりできる。
- 受け取った関数は、コピーした配列の `sort` にそのまま渡せばよい (自分で呼ぶ必要はない)。
- 比較関数を省略した場合、本物の `sort` は文字列として並べ替える (`[10, 9, 1].sort()`)。省略されたときの引数の値を調べるよう促された。
