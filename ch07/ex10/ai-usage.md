# AI 利用記録 (ch07/ex10)

- 日付: 2026-11-08
- 使用ツール: Claude Code (モデル: Claude Opus 5.5)
- 利用方針: 解答コードの生成は依頼せず、動的配列の仕組み (要素数と容量の違い、2 倍に拡張する理由)、各メソッドの役割分担、`this` の意味、テストの書き方、自分で書いたコードの不具合の原因についてヒントを受けた。解答 (index.js, index.test.js) は自分で作成した。

## プロンプトと得られたヒントの概要

### 1. 全体の考え方

> 問題7.10に関して考え方のヒントをください。indexを超えた時に新しいindexを代入して数があうようにpushをすればいい？あとindexの数が減ったときは要素を減らさなくていいんだっけ？indexを代入しなおしてsetをすれば短くなって余りはなかったことになる？

得られたヒント:

- 「利用者から見た要素数 `this.len`」と「内部の固定長配列の大きさ (容量) `this.array.length()`」の 2 つの長さを分けて考える。`len` より後ろは固定長配列に存在しても「存在しない」扱い。
- push は常に `this.len` 番目に書き込む。流れは「空きの確認 → (必要なら) 2 倍の配列を作ってコピー → `len` 番目に書き込み → `len` を 1 増やす」。
- この課題には要素が減る操作 (pop など) がないので、縮める処理は不要。
- set は既存の要素を書き換えるだけで長さを変えない。範囲チェックは `len` 基準で、範囲外はエラー。

### 2. なぜ 2 倍にするのか / 可変とは

> なんで空きがない場合は2倍のサイズの配列を作るの？可変ってそういうことなの？

得られた回答:

- 「可変」の正体は、中身は固定長のまま、足りなくなったら大きい配列を作って中身をコピーし、利用者からは伸びるように見せること。2 倍にすること自体が可変の定義ではない。
- +1 ずつ増やすと毎回再配置とコピーが起きるが、2 倍にすると再配置の頻度がどんどん下がる。コピー回数の合計の比較は問題 7.11 で取り組むよう促された。
- 大事なのは「足す」ではなく「一定の倍率で掛ける」こと。1.5 倍などを使う実装もある。

### 3. get の範囲外で push を呼ぶか

> getが実装しやすい？0よりindexが小さければエラーにして、長さを超えた場合はpushを呼ぶ？

得られたヒント:

- get は読むだけの操作なので、配列を変えるべきではない (問題 7.5 の副作用の話と同じ)。範囲外はどちら側もエラーにする。
- 長さを変えてよいのは push だけ、と役割を分けると整理しやすい。
- 本物の JS 配列は範囲外を読むと `undefined` を返すが、この課題では `makeFixedSizeArray` に合わせてエラーにするのが自然。

### 4. `len` と `length()` の違い

> lenとlengthって何が違うの？
>
> length()に関しては固定長のlength()ではなく、lenを返すんだよね？

得られた回答:

- `this.len` は要素数を覚えておくプロパティ、`length()` は利用者に要素数を教えるメソッド、`this.array.length()` は内部の固定長配列の容量。
- プロパティ名を `length` にするとメソッド `length()` と名前がぶつかるので `len` を使っている。
- 本物の JS 配列の `length` はプロパティ (カッコなし) だが、この課題ではメソッド。

### 5. 自分で書いた get の不具合

> つまり、getってindex.jsに書いたのでいい？

得られたヒント (自分で書いたコードに対する指摘):

- 範囲チェック (`index < 0 || this.len <= index`) は正しい。
- `return array[index]` の `array` は `makeFixedSizeArray` の中にしかない変数なので、クラスからは見えない。コンストラクタで保存した名前と、固定長配列は `get` / `set` を持つオブジェクトで `[index]` では取り出せないことを確認するよう促された。

### 6. 範囲外のエラーが出た

> console.log(a.get(1));を実行したときthrow new Error(`Array index out of range: ${index}`);でそもそも何かエラーがでたけど、newが使用禁止だったりした？

得られた回答:

- 自分で書いた throw が意図どおり動いた結果で、`new` が禁止されているわけではない。Node.js はエラーが投げられた行を `^` で示すので throw の行が表示される。
- エラー出力はメッセージ (`Error: ...`) とスタックトレース (`at ...`) を読む。止めずに確認したいときは `try...catch` を使う。

### 7. set と length()

> じゃあ、次はsetを書けばいいのか。getと同じようには書くけど、pushはしない？

得られたヒント:

- set は get と同じ範囲チェックをして、内部の固定長配列に書き込むだけ。push を呼ばない、`len` を変えない。
- `length()` は容量ではなく `this.len` を返す。

### 8. push の再配置とコピー

> this.array[...old]でコピーできる？
>
> 古い配列の要素を新しい配列にコピーするまでは書けた

得られたヒント:

- `obj[...]` の中にスプレッド構文は書けない。また `old` は反復可能 (iterable) なオブジェクトではないので `[...old]` も使えない。`old.get(i)` で取り出して新しい配列の `set` で入れることを for で繰り返す。
- 再配置が起きるのは満杯のときなので、`this.len` と `old.length()` は等しい。
- コピーで `this.set` を使うと `len` の範囲チェックをたまたま通るだけなので、内部配列の `set` を直接使う方が意図がはっきりする。`len` 番目への書き込みは `this.set` ではエラーになることを考えるよう促された。

### 9. `this.set` と `this.array.set` の違い

> this.array.setは古い方のメソッドだけど、そっちを使用するの？
>
> this.setとthis.array.setだと後ろの方は固定長になる？混乱してきた

得られた回答:

- `this.array = makeFixedSizeArray(...)` の後は、`this.array` は新しい配列、`old` は古い配列を指す。メソッドの種類と、どの配列に対して呼ぶかは別に考える。
- DynamicSizeArray (外側の箱・`len` でチェック) と固定長配列 (内側の箱・容量でチェック) の二重の箱の図で説明を受けた。利用者は外側の `set`、push は内側の `set` を使う。

### 10. 範囲外と空箱

> pushのindexをいきなり10とかにしたら、他の空の部分はundefinedになるよね？
>
> もともと初期値の容量は4だから、最初から4つの空箱はあるんだっけ？

得られた回答:

- push は index を受け取らず常に末尾に追加するので、隙間はできない。set(10, x) は範囲外でエラー。
- 本物の JS 配列で `arr[10] = "x"` とすると、間は穴 (疎な配列) になり、読むと `undefined`。
- コンストラクタで容量 4 の固定長配列が作られるので、最初から空箱が 4 つある (`len` は 0)。中身のない部分を読ませないために `len` で範囲チェックしている。

### 11. テストの書き方

> これで後はテストすればいい？
>
> 最初にコンストラクターを作って連続でテストする方が楽かな？何回も作るの無駄かなって

得られたヒント:

- テストから読み込むために `export` を付け、試し書きのコードは消す (またはコメントにする)。
- テストの観点: 初期状態、push と get、5 回以上の push (再配置)、set、範囲外 (負の index を含む)、容量内でも `len` の外ならエラー。
- インスタンスを全テストで使い回すと、前のテストの状態を引きずる・順番で結果が変わる・原因が追いにくい。テストごとに新しく作るか、`beforeEach` を使う。1 つのテストの中で連続して操作するのは問題ない。

### 12. テストでの `this`

> TypeError: Cannot read properties of undefined (reading 'length') this.array.length()がエラーになった
>
> (this の説明が) よくわからない

得られた回答:

- テストファイルの `this` はクラスのメソッドの中ではないので、インスタンスを指さない (`undefined`)。
- `this` は「自分」のようなもので、`arr.push(5)` ならドットの左の `arr` が push の中の `this` になる。クラスの中では `this`、クラスの外ではインスタンスを名前で呼ぶ。
- vitest を ch07/ex10 の中で実行すると `node_modules/.vite` のキャッシュができるので、リポジトリのルートで `npx vitest run ch07/ex10` を実行するとよい。
