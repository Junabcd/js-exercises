# AI 利用記録 (ch03/ex11)

- 利用ツール: Claude Code (Fable 5)
- 日付: 2026-09-07
- 利用方針: 解答コード (equals 関数) は書いてもらわず、オブジェクトの走査方法・再帰の仕組み・バグの原因調査のみ相談した。実装と修正は自力で行った。

## 相談内容 (プロンプトの要約) と得たヒント

1. **「プロパティって配列と同じような比較の仕方できる? 配列なら length で長さを比較して a[1] で中身を取り出せる」**
   → `Object.keys(obj).length` でプロパティ数、`obj[key]` (ブラケット記法) で値にアクセスできるという対応関係を教わった。変数に入ったキー名でのアクセスはブラケット記法のみ可能なこと、「個数を比べる → キーごとに値を === で比べる」という手順のヒントを得た。

2. **「for (const key in obj) って勝手に key の数だけループしてくれるの?」**
   → する。key に入るのはプロパティ名の文字列で、値は `obj[key]` で取り出す。for...in はプロトタイプ継承したプロパティも列挙する癖があること、for...of との違いを教わった。

3. **「`typeof o1 === null || typeof o1 !== "object"` のガードが先に走るのに null が次の行に抜けるのはなぜ?」**
   → typeof は常に文字列を返すので `typeof o1 === null` は常に false であること、`typeof null` は `"object"` になる仕様であることを教わり、`o1 === null` で直接比較する形に修正した。

4. **「for...in だと再帰的なもの (ネスト) はカバーしきれないか」**
   → その通りで、値がオブジェクトのとき `===` は参照比較になり中身を見ない。ループ内で値がオブジェクトなら自分自身を再帰呼び出しする方針と、冒頭のガードが再帰の基底ケースとして働くことのヒントを得た。

5. **「`if(typeof key === "object") equals(o1[key],o2[key]);` で再帰的に呼べると思ったけど違う?」**
   → 2 つの誤りを指摘された。(1) key は常に文字列なので typeof を見るべきは値 `o1[key]`、(2) 再帰の戻り値をどこにも使っておらず結果が捨てられている。

6. **「{pos: {a: 1}} の場合 key は "pos" と "a" になるの? 文字列は === で比較しないとだめでは?」**
   → for...in が列挙するのはその階層のキーだけで "a" は再帰先のループで初めて出てくる、という実行トレースで理解した。「ループ内で分岐する構造」と「何でも再帰に投げて基底ケースで === を返す構造」の 2 案を教わり、前者で実装した。

7. **「for...in で {pos: 1} と {pos: {a: 1}} は区別できない?」**
   → キーだけでは区別できず、値の typeof で区別する。片方だけオブジェクトのケースは === (必ず false) か再帰先の冒頭ガードが拾う構造になっていることを両方向のトレースで確認した。

8. **「break で抜けるようにしたが、ネストの深いキー数違いのケースだけ合わない」**
   → break はループを抜けるだけで関数からは抜けないため、再帰が返した false がループ後の `return true` に握りつぶされていた。`return false` で関数ごと抜けて false をリレーする必要があると教わった。

9. **「return false をすると再帰させる前に false で終わりにならない?」**
   → 再帰呼び出しの結果が出た後に return が実行される (順序が逆) こと、return するのは不一致のときだけで一致なら次のキーへ進むこと、不一致が 1 つでもあれば答えは false と確定するので即 return してよいことを教わった。

10. **「各呼び出しが自分の return を持つなら最終的に何が返る? false, false, true とか?」**
    → 各呼び出しは直接の呼び出し元に 1 個だけ値を返し、呼び出し元がそれを条件判定に使って自分の return を返すリレー構造。手元に届くのは一番外側の 1 個だけで、正しく伝播させれば false は false のまま届くことを理解した。

11. **「なんかまた合わない」(デバッグ相談)**
    → 再帰の if と `o1[key] !== o2[key]` の if が独立していて両方実行されるため、再帰が true でも直後の参照比較 (`!==`) で false になっていた。「オブジェクトなら再帰、そうでなければ === 比較」の排他的な分岐 (else) にすべきというヒントを得て自分で修正した。
