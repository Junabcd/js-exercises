# AI 利用記録 (ch03/ex14)

- 利用ツール: Claude Code (Fable 5)
- 日付: 2026-09-10
- 利用方針: 実行結果の予想と検証は自分で行い、AI には自分の理解の答え合わせと、腑に落ちない挙動の理由の解説を求めた。実行方法 (非 strict モード) のトラブルシューティングも相談した。

## 相談内容 (プロンプトの要約) と得たヒント

### let 版

1. **「let はスコープごとだから関数内の i=100 も関数内に閉じる。for のスコープで console しているから 0〜9 が出て、for の外の console は undefined になるのか?」**
   → 前半 (関数内の `let i = 100` は誰からも参照されない別変数、ループは 0〜9) は正しいと確認。ただし「外の console は undefined」には待ったがかかり、「変数は存在するが値が undefined」と「変数そのものが存在しない」の区別を考えて実際に実行して確かめるよう促された。

2. **「undefined じゃなくて『定義されていない』というエラーだった。let だからね」**
   → 正解と確認。`let` の `i` は for ブロックに閉じているため、外からは「変数自体が存在しない」→ `ReferenceError: i is not defined` になる、という理解で確定。

### var 版

3. **「var にしたら 100 が入るかと思ったのに入らないのがわからない。スコープは関係なくなるんじゃないの?」**
   → 誤解を訂正された。`var` は「ブロックスコープを持たない」だけで**関数スコープは持つ**。IIFE も関数なので、中の `var i = 100` はその関数のローカル変数になり (シャドーイング)、外の `i` には影響しない。`var` で「スコープが効かなくなる」のはブロック (for や if の `{}`) に対してだけで、そのため外側の `var i` はグローバルに属し、ループ外の `console.log(i)` がエラーにならない。

4. **「最後の i が 10 になるのがわからない。i が 9 でループを抜けるのに… あ、i が 10 になって条件を満たさなくなって抜けるから 10 が出るのか」**
   → 自力の後半の推論が正解と確認。ループは「条件チェック → 本体 → インクリメント → 条件チェック」の順なので、i=9 の本体実行後に `i++` で 10 になり、`10 < 10` が false で抜ける。抜けた時点の i は必ず 10。

### 宣言なし版 (非 strict)

5. **「非 strict モードで index.js を実行する方法は?」**
   → この repo は package.json に `"type": "module"` があるため `.js` は常に strict の ES モジュールになると教わった。対処として ①実験用コピーを `.cjs` 拡張子にして `node` で実行 (CommonJS はデフォルト非 strict)、②Node REPL に貼り付け、③ブラウザの DevTools Console、の 3 案を得た。①を採用。

6. **「100 と 101 だけ出るのが不思議。for 文 10 回が消えるわけでもないのに… 1 回目で 100 が代入されて、インクリメントで 101 になり 10 より大きいから抜ける。だから 2 つなのか」**
   → 正解と確認。宣言なしの `i = 100` は新しいローカル変数を作らず既存のグローバル `i` にそのまま代入する (関数の壁が消える) ため、ループカウンタ自体が破壊されて 1 周で終了する、という仕組みの解説を得た。

### まとめの観点

7. 3 パターンの違いの整理として、「関数内の `i = 100` が外に漏れるか」を決めるのは**宣言の有無**、「for の外から `i` が見えるか」を決めるのは **let か var か (ブロックスコープの有無)**、という 2 軸の見方を得た。説明文は自分でまとめた。
