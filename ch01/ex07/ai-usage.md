## 質問したプロンプトと得られた回答の要約

1. **「class を引数に渡すやり方と、テストコード用に export と import するやり方を教えて」**
   - クラスのインスタンスは数値や文字列と同じ「ただの値」なので、そのままメソッドの引数に渡せる。メソッド内では `this`(自分自身)と引数(相手)の両方のプロパティにドットでアクセスできる。例として Point とは別の Wallet クラスで `merge(other)` の形を提示された。
   - export / import は `export class Point { ... }`(名前付きエクスポート)と `import { Point } from "./index.js";` の組み合わせで、すでに正しい形になっていた。ファイル末尾に `export { Point };` とまとめて書く方法もある。
   - 注意点として、import するとファイルのトップレベルのコードが全部実行されるため、index.js に残っていた動作確認用コード(定義していない `p.distance()` の呼び出し)が import 時にエラーになることを指摘された。export するファイルには定義だけを置くのが定石。
   - テストファイルに ex06 の `fib()` のテストがコピーのまま残っていることも指摘され、配列やオブジェクトの比較には `toBe` ではなく `toEqual` を使うというヒントを得た。

2. **「class Point のメソッドの引数として Point という名前も可能？紛らわしいから引数名は変えた方がいい？」**
   - 文法的には可能だが、引数名がクラス名をシャドーイング(覆い隠し)するため、メソッド内で `new Point(...)` を使いたくなったときに引数(インスタンス)を new しようとして TypeError になる。読む人にも紛らわしいので避けるべき。
   - 慣習的な引数名として `other`(相手側の意味で一番よく使われる)や、小文字の `p` / `point` を勧められた。JavaScript ではクラス名は大文字始まり、変数は小文字始まりが慣習。
