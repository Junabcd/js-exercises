# AI 利用記録 (ch04/ex06)

利用 AI: Claude Code (Claude Fable 5)
日付: 2026-09-21

解答コードは自分で作成した。AI には完成コードの提示は求めず、演算子の仕様に関するヒント、REPL での確認方法、Vitest での console.log のテスト方法のみを質問した。

## 質問した内容と得られたヒント

### 1. `(params && params.maxWidth) &&= 2` は何に代入されるのか

- 質問: `if (params && params.maxWidth)` を `&&=` で書こうとして `(params && params.maxWidth) &&= 2` とした場合、何に 2 が代入されるのか分からない。
- 回答: `a &&= 2` は `a && (a = 2)` に展開されるので、`&&=` の左辺は「値を読む」と「代入する」の両方に使われる。代入演算子の左辺に置けるのは変数名やプロパティアクセスなどの「代入先として参照できるもの」だけで、`a && b` のような演算結果 (一時的な値) は代入先になれないため、この式は "Invalid left-hand side in assignment" 系のエラーになる、というヒントを得た。Node REPL で実際に試して確認した。

### 2. `if (params && params.maxWidth) maxWidth = params.maxWidth;` を演算子で書き換える

- 質問: params があって maxWidth プロパティがあるときに変数 maxWidth を params.maxWidth で置き換えたい。
- 回答: 実際の代入先は変数 `maxWidth` であること、`&&=` の条件は「左辺」にかかるので今回の「右辺が truthy なら上書き」とは条件の向きが逆であることを指摘された。オプショナルチェーン `?.` と `||` / `??` を組み合わせる方向のヒントを得た。

### 3. `&&` と `||` だけでも書けるか

- 質問: `?.` や `??` を使わず `&&` と `||` だけでも書けるか。
- 回答: `&&` と `||` は boolean ではなくオペランドの値そのものを返すこと、`params && params.maxWidth` は代入の左辺には置けないが値を計算する式としては合法であること、`||` の右側に「元の maxWidth」を置けば「条件を満たさなければ変わらない」が表現できること、のヒントを得て自分で組み立てた。

### 4. `a && (b = ...)` のように右側に代入式を置く書き方

- 質問: `a && b` の b に代入式を置くのはありか。
- 回答: 代入は値を返す「式」なので `&&` のオペランドに置ける。短絡評価により `a && (b = 2)` は `if (a) b = 2;` と同じ動きになる。ただし `&&` は `=` より優先順位が高いので代入式側のカッコは必須 (ないと最初の質問と同じエラーに戻る)。ESLint の no-unused-expressions 系警告が出る可能性があることも教わった。

### 5. Vitest で `console.log({ maxWidth, maxHeight })` をテストする方法

- 質問: console.log を spy 化して、記録したものとログ出力を比較するようなことはできるか。
- 回答: `vi.spyOn(console, "log").mockImplementation(() => {})` で spy 化し、`expect(spy).toHaveBeenCalledWith({ maxWidth: 600, maxHeight: 480 })` でオブジェクトごと深い等価比較できると教わった (ツールの使い方なので具体例あり)。`spy.mock.calls` で生の引数も確認できる。テスト後は `vi.restoreAllMocks()` で戻す。別解として、関数は値を return してログは呼び出し側で行う設計にすれば spy が不要になることも教わった。

### 6. `params?.maxWidth` の安全性の範囲

- 質問: `?.` は params が undefined のときは安全だが、maxWidth プロパティがなくてもエラーにならないのか。
- 回答: 存在しないプロパティの読み取りが `undefined` になるのは `?.` 以前からの JS の仕様で、エラーになるのは「null / undefined に対するプロパティアクセス」だけ。`?.` が守るのはそのケースのみ。チェーンを深くする場合は「nullish になりうる段の直後」に `?.` を置く必要があることも教わった。

### 7. `a?.b?.c` のように複数使えるか (余談)

- 質問: `?.` は複数連結できるのか。
- 回答: 各段に付けられる。チェーンのどこかで nullish に当たると式全体が `undefined` に短絡する。`obj?.[key]` や `func?.()` の変種もあるが、付けすぎるとバグを隠すので「無いのが正常」な段にだけ付けるのがよい、と教わった。

### 8. テストが合わないときのデバッグ

- 質問: `params?.maxWidth ?? maxWidth;` と書いたら maxWidth プロパティがあるケースでテストが合わない。
- 回答: (1) 式を評価しただけで結果をどこにも代入していないので maxWidth が更新されない、(2) 代入を直しても `??` は nullish のみ判定するため、元の `if` の truthy 判定とは `0` / `""` / `false` で結果が分かれる、という 2 つの確認ポイントをヒントとして得て、自分で修正した。
