## 質問したプロンプトと得た内容

1. **「console.log で出力されるものを expect とかでテスト可能だっけ？」**
   - `vi.spyOn(console, "log")` でスパイ化し、`spy.mock.calls` で呼び出し内容を検証できると知った。`mockImplementation(() => {})` で実出力を抑制できることも確認した。
2. **「スパイ化ってそもそもどんなの？」**
   - スパイは既存の関数を「呼び出しの記録係」にすり替えるテスト技法で、JS では関数の差し替えで実現できるという仕組みを理解した。スパイ・モック・スタブの用語の違いも確認した。
3. **「vi.restoreAllMocks() ってしなければいけないんだっけ？」**
   - 1 テストなら必須ではないが、テスト追加時の事故防止のため `afterEach` で戻すのが定石と理解した。あわせて、スパイの記録は累積するので関数ごとに `mockClear()` で区切ること、配列の比較は `toBe` ではなく `toEqual` を使うことを知った。
4. **「expect で比較した後にスパイを戻せばいいの？」**
   - `expect` は失敗時に例外を投げるため、後片付けをテスト本文の最後に書くと失敗時に実行されない。成功・失敗にかかわらず実行される `afterEach` に置くべきと理解した。
5. **「vitest が設定済みなら afterEach の import は不要では？」**
   - Vitest の `globals` 設定の話と確認。このリポジトリの `vitest.config.js` には `globals: true` がないため import が必要と判明。ついでに、リポジトリ内の大半のテストが `--globals` フラグ前提で書かれており、素の `npm test` では 33 ファイルが失敗することが分かった (対処は別途検討)。
6. **「なんで node index.js でコンソールの中身出てこないんだ？」**
   - 関数を定義しているだけで呼び出していないのが原因と指摘を受けた。また、ES モジュールは strict モードになるため、宣言なしの `for (i = 1; ...)` は呼び出し時に ReferenceError になるというヒントを得た (修正は自分で実施)。
7. **「`i % 5 ? i : "Buzz"` って i が 5 で割り切れたら i を表示になっていない？」**
   - 条件が `i % 5 === 0` ではなく剰余そのものであり、`0` は falsy なので「割り切れたら `"Buzz"`」になると理解した。truthy/falsy を利用して条件の意味が反転しているのが読みにくさの原因で、これが問題 4.2 の出題意図につながると納得した。
