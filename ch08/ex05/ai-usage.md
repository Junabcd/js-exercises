# AI 利用記録 (ch08/ex05)

- 日付: 2026-11-19
- 使用ツール: Claude Code (モデル: Claude Opus 5.5)
- 利用方針: 解答コードの生成は依頼せず、オブジェクトへのプロパティの追加方法、キーの扱い、`const` とオブジェクトの関係、エラーメッセージの英語表現について質問した。index.js は自分で書く。

## プロンプトと得られたヒントの概要

### 1. ループでオブジェクトを作る方法と、文字列をキーにするときの注意

> 問題8.5で文字列と任意の値を交互に配列の中に入っている場合、ループで回してオブジェクトを作成したい。
> "a",1,"b",2の場合{a:1,b:2}のようにする。文字列がキー名になって、その次の値がバリューになる。for文で順番に取り出すけど、オブジェクトにする際にどうすればいいんだろうなって悩んでいる。配列の場合はpushとかでできるけど、objectだとそんな便利なものあったっけなって。
> あと、文字列をキーにするときって文字列のまま入れると違うことになるんだっけ？

得られた回答:

- オブジェクトには `push` のような専用メソッドはなく、`obj["x"] = 10` のように存在しないキーへ代入すればプロパティが追加される。
- ドット記法 `obj.key` は文字どおり `"key"` がキー名になり、変数の中身は使われない。ブラケット記法 `obj[key]` は式を評価した結果がキー名になる。変数をキーにするならブラケット記法を使う。
- `{a: 1}` と `{"a": 1}` は同じオブジェクト。数値をキーにしても文字列に変換される。

得られたヒント:

- 2 個ずつペアで扱うので、`for` のカウンタの増やし方を工夫する。
- 1 回のループでキーと値をどのインデックスから取り出すかを考える。
- 例外チェック (個数が偶数か、キーが string か) をループの前でするか中でするか考える。
- 別解として `Object.fromEntries()` を MDN で調べ、for 文版と比べてみる。

### 2. `obj[変数]` の結果は `{a: }` と `{"a": }` のどちらになるか

> じゃあ、obj[変数]で変数が"a"の場合は{a:}に勝手になるってこと？{"a":}にはならない？

得られた回答:

- どちらも同じで、キーは内部では常に文字列 `"a"` として持たれている。クォートの省略はソースコードの書き方の違いにすぎない。
- `console.log` では識別子として書ける名前はクォートなし、`my-key` のような名前はクォート付きで表示される。`JSON.stringify` は必ずダブルクォートを付ける。
- テストの `toEqual({ a: 1 })` と `toEqual({ "a": 1 })` は同じ結果になる。

### 3. `const` で宣言したオブジェクトにプロパティを追加できるか

> const obj = {};
> objの値を書き換えるわけではなく、プロパティを追加するからconstでもいいんだっけ？

得られた回答:

- `const` が禁止するのは変数への再代入だけで、オブジェクトの中身の変更 (追加・書き換え・削除) は禁止しない。
- 変数に入っているのはオブジェクトへの参照で、`const` はその参照を固定する。`obj = { b: 1 }` は TypeError になる。
- 中身の変更も禁止したい場合は `Object.freeze()` を使う。

### 4. エラーメッセージの英語表現

> valueの長さが偶数じゃないよ
> 文字列じゃないとだめだよ
> の2つの文をエラー文として英語で書きたい。

得られた回答:

- 偶数でない場合: `The number of values must be even.` / `Expected an even number of arguments, but got 3.`
- 文字列でない場合: `Key must be a string.` / `Expected a string key at index 2, but got number.`
- 実際の値や位置をメッセージに含めるとデバッグしやすい。

得られたヒント:

- `Error` 以外に `TypeError` (型が違う) や `RangeError` (値が範囲外) があるので、どちらがどちらの状況に合うか MDN で調べて選ぶ。
- テストで `toThrow(TypeError)` のようにエラーの型まで確認できる。
