# AI 利用記録 (ch08/ex06)

- 日付: 2026-11-20
- 使用ツール: Claude Code (モデル: Claude Opus 5.5)
- 利用方針: 解答コードの生成は依頼せず、残余引数とスプレッド構文の違い、`push` の使い方、破壊的メソッドを使ってよいかについて質問した。index.js は自分で書く。

## プロンプトと得られたヒントの概要

### 1. 残余引数で受け取った値を代入式で入れてよいか

> 問題8.6でargumentを使わないので、...を使用して同様のものを作成するが、引数を単にスプレッド構文で書くと分解して代入されてしまうので、arg[0],arg[1]などにはならない。
> そこで、受け取ったものを代入式でいれることを考えたが、それっていいんだっけ？

得られた回答:

- `...` は書く場所によって働きが逆になる。呼び出し側の `f(...arr)` はスプレッド構文で、配列をばらして渡す。定義側の `function f(...xxx)` は残余引数で、ばらばらの引数を 1 つの配列にまとめる。
- 別の変数に代入してもエラーにはならないが、残余引数がすでに配列になっているなら代入は余計な手順になる。

得られたヒント:

- 課題とは別の関数 `show(...xxx)` を作り、`xxx` の中身と `Array.isArray(xxx)` を予想してから実行してみる。
- 元のコードでなぜ `Array.from(arguments)` が必要だったのかを、MDN の arguments のページの「配列ではない」という説明と比べて考える。残余引数を使うときに `Array.from` が要るかどうかもそこから判断する。

### 2. `push` すると分解されて入ってしまうのではないか

> argが[]になって最初はpushとかで[...values]とかに仕様かと思ったけど、分解して入れられてしまうからダメだなって思って

得られた回答:

- `push(...values)` は `values` がばらされて、要素が 1 つずつ追加される。
- `push(values)` は配列そのものが 1 要素として追加される。
- `push([...values])` は、ばらした要素を `[ ]` で新しい配列にまとめ直してから 1 要素として追加する。分解されたまま入るわけではない。

得られたヒント:

- 3 つの書き方の結果を予想してから実行し、`args[0]` が `[1, 2, 3]` になるのはどの形かを考える。
- `push(values)` と `push([...values])` の違いは、入るのが元の配列そのものかコピーかという点。`b[0] === values` のように比べると確かめられる。

### 3. 破壊的メソッドの `push` は使わない方がいいか

> あー、pushって破壊的関数だからあまり使わない方がいいんだっけ？

得られた回答:

- 「破壊的メソッドは使わない」は絶対のルールではなく、場面による。
- 避けたほうがいい場面は、引数で受け取った配列を書き換えるとき、同じ配列を複数の場所で共有しているとき、React の state のように新しい配列を作ることが前提の仕組みを使うとき。こういうときは `concat` や `[...arr, x]` で新しい配列を作る。
- 8.6 は `args` に記録をためていくことが目的なので、`push` で書き換えるのが意図した動作であり、使って問題ない。
- 元のコードの `args` は `const` なので `args = [...args, x]` のような再代入はできない。この点からも `push` で書き換える前提のコードだと分かる。
