# AI 利用記録 (ch08/ex01)

- 日付: 2026-11-14 〜 2026-11-15
- 使用ツール: Claude Code (モデル: Claude Opus 5.5)
- 利用方針: 解答コードの生成は依頼せず、問題の意図、関数名の付け方、Vitest でのテストの書き方についてヒントを受けた。

## プロンプトと得られたヒントの概要

### 1. 小問 1 の処理は複雑にならないか

> 問題8.1でコンソールにn回出力したり、配列を作成したりって結構複雑にならない？

得られたヒント:

- 8.1 で問われているのはアルゴリズムではなく、アロー関数の書き方の違い。
  - 小問 1: 処理が複数あるので `{ }` と `return` が必要になるケース
  - 小問 2: 式 1 つなので `{ }` と `return` を省略できるケース (引数 1 つなら `( )` も省略可)
  - 小問 3: オブジェクトを返すときに `{` がブロックと解釈される問題への対処
- 小問 1 は「出力する」と「配列を作る」の 2 つに分けて考えればよい。出力は `for` 文で書ける。配列は `push` のほか、`Array.prototype.fill()` や `Array.from()` を調べるよう促された。
- 問題とは別の小さな例で、式 1 つのアロー関数とブロック本体のアロー関数の違いを確認した。

### 2. 小問 1 の関数名

> 問題8.1の1のような関数って関数名どんな英名がいいんだろう？

得られたヒント:

- 関数名は動詞から始める camelCase が一般的。出力という副作用がある場合は、それも名前に含めると呼び出し側が驚かずに済む。
- 候補として `logAndRepeat`、`repeatAndLog`、`printAndCollect`、`logCharTimes`、`repeatChar` が挙がった。
- `String.prototype.repeat()` が「繰り返した文字列を返す」ことも、単語の使い方の参考として紹介された。

### 3. console が呼ばれたことのテスト

> テストコードでconsoleが呼ばれたことをテストするのってどう書くんだっけ？

得られた回答 (ツールの使い方なので具体例あり):

- `vi.spyOn(console, "log").mockImplementation(() => {})` で監視し、実際の出力を抑える。`afterEach` で `vi.restoreAllMocks()` を呼んで元に戻す (ch04/ex06 と同じ書き方)。
- `toHaveBeenCalledTimes`、`toHaveBeenCalledWith`、`toHaveBeenNthCalledWith`、`not.toHaveBeenCalled`、`spy.mock.calls` で回数や引数を確認できる。
- `n = 0` のような境界のテストも入れるとよい。
- `vitest.config.js` に `globals: true` があるので、`vi` や `expect` は import しなくてもよい。

### 4. アロー関数のテストの仕方

> アロー関数って普通に引数渡して関数呼ぶ感じでテストしてはいけない？

得られた回答:

- アロー関数も普通の関数と同じように、引数を渡して呼べばテストできる。
- `export const 名前 = (...) => ...` の形で export する。
- `const` に代入したアロー関数は巻き上げられないので、定義より前の行では呼べない (import して使う分には関係ない)。
- 小問 3 は現在時刻が入るので、値の完全一致ではなく、プロパティの有無や型で確かめる方法を考えるよう促された。

### 5. 現在時刻 `now` のテスト

> nowを呼んだ時、値がなんか返ってきていることをテストする場合はどのようなテストコードで書ける？

得られた回答 (ツールの使い方なので具体例あり):

- `toHaveProperty("now")` でキーがあることを、`toBeDefined()` で値が `undefined` でないことを確かめる。
- 型は、Date なら `toBeInstanceOf(Date)`、数値なら `typeof` で確かめる。`now` に何を入れるかは自分で決める。
- `vi.useFakeTimers()` と `vi.setSystemTime()` で時計を固定すると、値を完全一致で比べられる。Date 同士は `toBe` ではなく `toEqual` で比べる。
- 呼び出し前後の `Date.now()` で挟んで範囲を確かめる方法もある。

### 6. 戻り値に直接プロパティアクセスできるか

> 関数を呼んだものに直接.propみたいにプロパティをつけて確かめられないから、何かに一旦代入する必要あるよね？

得られた回答:

- `getNow().now` のように、関数呼び出しの結果に直接 `.` でつなげられる。代入は必須ではない。
- ただし `getNow()` と書くたびに関数が別々に呼ばれる。同じ戻り値を複数の観点で確かめたいときや、前後の時刻で挟むときは、1 回呼んで変数に入れる。
- 括弧に注意が必要なのは、アロー関数を定義するときにオブジェクトリテラルを返す場合。呼び出した結果を読む側では括弧は要らない。
