# 問題8.3
## 問題1
末尾再帰の最適化では末尾呼び出しの除去を行っている。  
通常のプログラムの実行モデルでは、関数を呼び出すと、関数自身のローカル変数や戻り先情報を保持するスタックフレームが生成されてコールスタックと呼ばれるスタックにpushされる。関数はスタックフレームに計算途中の値を保持しつつ処理を続け、関数の実行が終わると対応するスタックフレームがpopされて呼び出し元のスタックフレームに復帰し、呼び出し元関数の実行が再開される。  
例えば以下のような関数があるとする。
```javascript
function foo(x) {
	return sum(x, x); // (A)
}

function sum(a, b) {
	return a + b;
}

foo(2); // (X)
```

### 末尾呼び出しの除去を行わない場合  
位置(X)でfooを呼び出した直後は次のようになる。
```
コールスタック
foo:{x:2}:returnTo:(X)
```
次に、(A)の位置でsum関数を呼び出した直後は次のようになる。
```
コールスタック
sum:{a:2, b:2}:returnTo:(A)
foo:{x:2}:returnTo:(X)
```
関数sumが終了するとスタックフレームがpopされ、returnToが示す(A)の位置からfooの関数の実行が再開される。_tmp変数にsumの戻り値が格納されるとすると、
```
コールスタック
foo:{x:2, _tmp:4}:returnTo:(X)
```
となり、最後にfooは_tmpの値をリターンして終了する。

### 末尾呼び出しの除去を行う場合  
fooの呼び出し直後のコールスタックは次のようになる。
```
コールスタック
foo:{x:2}:returnTo:(X)
```
次に、(A)でsum関数を呼び出す。末尾呼び出しの除去を行う場合、fooのスタックフレームをsumのコールスタックとして再利用する。  
このとき、コールスタックは次のようになる。
```
コールスタック
sum:{a:2, b:2}:returnTo:(X)
```
sumのリターン値（実行結果）がそのままfooのリターン値となる。

### 末尾再帰の最適化
末尾再帰は自分自身を末尾呼び出しする再帰関数であり、末尾呼び出しの除去を利用できる。  
末尾呼び出しの除去を利用することで、スタックフレームが再利用され、メモリの使用量を減らすことができる。  
その結果、深い再帰でもスタックフレームが大量に作られることがなくなり、スタックオーバーフローを避けることができる。

## 問題2
### 末尾再帰最適化を実装している処理系
ES6の仕様には末尾再帰最適化があるが、それに対応しているブラウザがSafariくらいしかない。  
Node.jsでは一時期--harmonyオプションをつけることで末尾再帰最適化ができていたみたいだが、現在のバージョンでは非対応になっている模様。  
ChromeやFirefoxも非対応。  

### 実行結果
問題8.3に記載されているURLをChrome、Firefox、Safariの3つのブラウザでそれぞれ実行した。  
実行結果は以下のようになった。
```
Chrome：
[ERR]: "Executed JavaScript Failed:" 
[ERR]: Maximum call stack size exceeded 

Firefox：
[ERR]: "Executed JavaScript Failed:" 
[ERR]: too much recursion

Safari：
[LOG]: Infinity
```
Safariでは実行できることを確認できた。
