- **AI の回答概要**:
  - 本質は eval と同じコードインジェクション。`${input}` がクォートで囲まれていないため、入力がデータではなくコードとして実行される。被害は実行場所で変わる (ブラウザ: Cookie 窃取など XSS 相当、Node.js: 環境変数の読み取りやプロセス停止など任意コード実行)。Node.js はシングルスレッドなので、無限ループは全利用者に影響する DoS になる。
  - `new Function` の本体はグローバルスコープで実行されるので、ローカル変数は見えないが `process` / `document` / `fetch` などのグローバルには触れる (どれが存在するかは環境による)。
  - `const s = "World"` のクォートは JS の文法で、値は `World` の 5 文字。そのため本体が `return "Hello, " + World` となり ReferenceError になる (ローカルが見えないこととは別の原因)。`f(typeof fetch)` も呼び出し側で先に評価されるので同じ問題が起きる。コードとして解釈させたいなら `f("typeof process")` のように全体を文字列で渡す。
  - `process.env` には OS の環境変数が最初から入っているが、丸ごと出力するとユーザー名やパスが出るので、ダミーの値だけを読むのが安全。
  - `--env-file` のパスはカレントディレクトリからの相対パス。また `--env-file` を付けずに実行すると .env は読み込まれず、`process.env.DUMMY_API_KEY` は `undefined` になる。
  - `/.env)` は正規表現リテラルとして解釈され SyntaxError になる。`console.log` にファイルを読む機能はない。
  - オブジェクトを文字列と `+` で連結すると `toString()` が呼ばれて `[object Object]` になる。特定のプロパティを指定すればよい。
  - `while` は文なので、式の位置 (`"Hello, " + ここ`) には書けない。即時実行関数で包めば、中に文を書けて全体は式になる。`while (条件) { 処理 }` の書き方、`let` での宣言、クォートの入れ子 (内側は `'...'`) に注意。
  - `+` は両辺の値を計算してから連結するため、右辺の即時実行関数は連結の前に実行され、副作用 (出力、ループ、外部送信など) はすべて起きる。連結に使われるのは戻り値 (`undefined`) だけで、`Hello, undefined` は最後に表示される。式を書ける位置に入力が埋め込まれる時点で、任意のコードを実行できる。
  - プッシュ前の確認として、ex13 内のファイルに本物の秘密情報や環境変数の全出力が含まれていないことを確認した。
