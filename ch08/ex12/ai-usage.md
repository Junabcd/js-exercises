# AI 利用記録 (ch08/ex12)

## 2026-11-24: Function コンストラクタを使った関数 f の考え方を質問

- **利用 AI**: Claude Code (Claude Opus 5.5)
- **プロンプト** (要旨、時系列順):
  1. > 引数として $1~$10 と実行部分を分けて書く必要がある。前半は残余パラメーターで最後の引数を実行部分として文字列で受け取って実装するんだろうけど、文字列の部分を関数として動かすよって書き方あるんだっけ？
  2. > "$1"～"$10" って並べて書いた上に、実行部分も引数として受け取るけど、この時の文字列何でもいい感じ？
  3. > function(fn) の fn のように自由に決められる？ "fn" とかってしてもいいの？ ()() のように分かれている？
  4. > "" をつけるのとつけないのでかわるのか？
  5. > 引数として "" 付きで実行部分を直接渡されていても、new Function("","",fn) のように書けば区別できるんだっけ？
  6. > 書いてみたけど、変数名が定義されていないで即ダメ
  7. > 問題の意図としては Function() を使用してとあるが、層 1 で f として作成することは意図とあっている？
  8. > テストでの渡し方と Function での受け取り方がイメージわかない
  9. > f("$1 + 1")(1) を渡したときの動きって、fn の引数として "$1 + 1" が渡されて、関数ができる、その関数に (1) を渡すってこと？
  10. > { か分岐させるのってテストがそうなってるからってだけ？
  11. > 先頭に空白があると startsWith は空文字を先頭として認識するの？
  12. > 引数が文字列前提で fn.trim() とかって書けるってこと？
  13. > return を文字列にして連結したものを fn に入れるってことか
- **AI の回答概要**:
  - `new Function("x", "y", "return x + y")` のように、最後の引数が関数本体 (文字列)、それより前が引数名 (文字列) になる。文字列を関数にする仕組みは Function コンストラクタ自体。
  - `f` 自身は本体の文字列 1 つだけを受け取る普通の関数 (層 1) で、その中で `new Function` を呼んで関数を作って返す (層 2) という 2 層構造。引数名 `$1`～`$10` は f の中で固定で用意すればよい。
  - 本体の文字列は JS として正しい必要がある (生成時に SyntaxError、実行時に ReferenceError 等)。本体からは引数とグローバル変数しか見えず、f のローカル変数は見えない。
  - `"body"` (文字列リテラル) と `body` (変数の値) の違い。`f("$1 + $2")` と呼ぶと引数 `fn` に文字列が代入されるので、`new Function(..., fn)` と引用符なしで渡せばよい。引数名に空文字は使えない。
  - 最初の実装 (`export const f = new Function(..., fn)`) が ReferenceError になったのは、`fn` を受け取る層 1 がなかったため。
  - `f("$1 + 1")(1)` は「f が関数を返す → その関数を $1 = 1 で呼ぶ」の 2 段階。`toString()` で生成された関数のソースを確認できる。
  - 式 (`"$1 + 1"`) は `return` が無いため `undefined` になるので先頭に `return ` を付ける必要がある。`{` で始まるブロックに `return` を付けると SyntaxError になるため分岐が必要。これはアロー関数の「式 / ブロック」と同じ考え方。
  - `startsWith` は空白も 1 文字として扱う。`trim()` してから判定するとよい。`return` の後のスペース、先頭改行による ASI に注意。
- **備考**: AI は考え方のヒント・小さな例 (引数 1 つ版の `makeFn` など) の提示とエラー原因の説明のみで、解答コード (`index.js`) は自分で作成した。

## 2026-11-24: 実装後の確認 (改行で始まる文字列と trim)

- **利用 AI**: Claude Code (Claude Opus 5.5)
- **プロンプト**:
  > 改行で始まる文字列って trim でどうにかなるの？
- **経緯**: 自作の `index.js` (テスト 4 件パス) について、AI から「判定には `fn.trim()` を使っているが連結は `"return " + fn` のままなので、`f("\n$1 + 1")` のように改行で始まると ASI により `undefined` が返る」と指摘を受けた。
- **AI の回答概要**:
  - `trim()` はスペースだけでなく改行 (`\n`, `\r`) やタブ (`\t`) も前後から取り除くため、連結にも trim した値を使えば解決する。
  - trim が消すのは前後のみで途中の改行は残るが、`return $1\n+ 1` のように次の行が続きとして解釈できる場合は ASI でセミコロンは挿入されないので問題ない。問題になるのは `return` の直後で改行される場合だけ。
  - 修正後は `f("\n$1 + 1")(1)` が `2` になるテストを追加すると確実。
- **備考**: 解説のみで、コードの修正は行っていない。
