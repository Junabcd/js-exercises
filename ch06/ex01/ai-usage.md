# AI 利用記録 (ch06/ex01)

- 日付: 2026-10-13 〜 2026-10-14
- 使用 AI: Claude Code (Opus 5.5)
- 用途: 実装の進め方のヒント、ハッシュ関数・リンクリスト・参照の考え方の理解、自作コードのレビューと動作確認、Vitest でのテストの書き方の調査。解答コードの生成は依頼せず、ヒントと小さな例をもとに自力で実装した。

## 質問したプロンプトと得られた回答の要約

1. **「問題の意図はなんとなくわかったけど、実装イメージの 1 歩目がわからず手が動かない」**
   - 「ハッシュ関数 → 衝突を無視した put / get → 衝突対応 (リンクリスト) と remove」の 3 段階に分けて、1 つずつ動かしながら進める方針をもらった。メソッドの中では `this.entries` / `this.size` で参照すること、メソッドをアロー関数で書かないこと、capacity 1 にすると衝突を確実に起こせることも教わった。

2. **「ハッシュ値への変換の仕方っていろいろあるよね？」**
   - 必須条件は「同じ入力なら同じ値」、努力目標は「値がバラけること」。方式には、文字コードの合計、多項式ハッシュ (Java の `hashCode` は係数 31)、djb2 / FNV、暗号学的ハッシュ (この課題には不要) がある。まず合計で作り、余裕があれば多項式に改良する。多項式にする場合は `Number.MAX_SAFE_INTEGER` を超えないように注意する。

3. **「ハッシュ関数はハッシュテーブルのひな型とは別に作る必要がある？」**
   - 別の関数として外に置き、export するのがおすすめ。問題文も 2 つを分けて書いており、単独でテストできて役割も分かれる。

4. **「charCodeAt と codePointAt はどっちがいい？」**
   - 違いはサロゲートペア (絵文字など) の扱いだけ。ハッシュでは同じ入力から同じ値が出れば良いので、`charCodeAt` で十分。

5. **「`{ key, value, next }` のどこにインデックスが絡むの？」**
   - インデックスはノードの中に保存しない。key から `hash(key) % capacity` で毎回計算する「配列上の置き場所」。ノードに key を保存するのは、同じインデックスに複数のノードが連なったときに見分けるため。

6. **「entries と size は使うの？」「push ではなく `[index] =` の代入？」「`{ key: key, ... }` と書く？」**
   - 両方使う。固定長の配列なので、位置を指定する代入を使う (`push` は末尾に追加され、長さが変わる)。プロパティ名と変数名が同じなら `{ key, value, next: undefined }` と省略できる。

7. **「ドット記法とブラケット記法」「`node[key]` の意味」「`.value` は変数がなくてもエラーにならない？」**
   - `node[key]` は変数 key の中身 ("key1" など) をプロパティ名として探すので、`node.key` とは別物。`.value` はプロパティの読み取りなので変数の有無とは無関係で、存在しなければ undefined が返る。TypeError になるのは、ドットの左側が undefined / null のとき。空の位置を読むときの対策として `?.` を使った。

8. **「sample() だけでは衝突を確かめられないからテストを書くってこと？」**
   - その理解で正しい。sample() では key1 と key2 のインデックスが 8 と 9 に分かれ、衝突が起きない。衝突をきちんと処理しない実装でも sample() は通りうるので、capacity 1 などでテストして補う。

9. **リンクリストの理解 (「先頭ノードを見る / 順番に見る / 上書きがよくわからず混乱」「node ってそもそも何？」)**
   - 箱を手で 3 つつないで `a.next.next` とたどる練習をした。`let node = 先頭` から `node = node.next` で進むループで「順番に見る」を理解した。node は「今見ている箱」を指す、自分で作るただの変数。

10. **put の衝突対応 (「同じインデックスなら next に代入？」「key 一致なら next に入れていい？」「else は要る？」「return は要る？」)**
    - 新しい箱をぶら下げるのは先頭ではなく、最後の箱の next。同じ key があれば value を上書きし、size は増やさない (key 一致で next に入れると、後ろの箱が消えて重複が生じる)。`while (node.next !== undefined)` だと最後の箱の key がループ内でチェックされないので、ループの後でもう一度チェックする。`return` は値を返すためではなく、上書き後に関数を抜けるために使う。空の判定は null ではなく `=== undefined`。

11. **remove (「delete だと empty になる？」「value を undefined にする？」「どうやって消す？」「先頭のイメージがわかない」)**
    - remove は value を消すのではなく、箱をつながりから外す操作。「1 つ前の箱の next」(先頭なら `entries[index]`) に「消したい箱の next」を代入すれば、外れた箱は誰からも指されなくなり、ガベージコレクションで片付けられる。`prev` を undefined で始めれば先頭かどうかを判定できる。更新は prev → node の順。ループ条件は全部の箱をチェックする `node !== undefined` にする。見つからないときは何もしない。

12. **自作コードのレビュー (「remove ってこれでいいかな？」「これでいいかな？」)**
    - 先頭のケースで、ローカル変数 `node` に代入していて `entries` が書き換わっていなかった。`size--` は `this.size--` にする必要があった。put のループに `node = node.next` がなく、無限ループになっていた。変数への代入と、オブジェクトのプロパティへの代入の違い (参照) を教わって修正した。最終版は AI がスクラッチファイルから容量 1 の衝突ケース (上書き・get・先頭 / 途中 / 末尾の remove・存在しない key) を実行し、すべて期待どおりであることを確認した。

13. **入力のチェック (「hash に文字列以外を渡すと変な挙動になる？」「`put(1)` だとどうなる？」「エラーメッセージの英語は？」)**
    - 数値は length がないため、黙って 0 になる。`typeof` で文字列でなければ `TypeError` を投げるようにした。`put(1)` は key = 1、value = undefined になり、hash で TypeError になる。value はどんな型でも格納できるが、undefined だと「存在しない」と区別できない。メッセージは `key must be a string` など。

14. **テストの書き方 (「衝突パターンの作り方」「put は return しないから toEqual で比べられない？」「capacity 10 だと entries 全部書く？」)**
    - capacity 1 のほか、並べ替えた文字列 ("ab" と "ba")、ハッシュ値の差が capacity の倍数になる key で衝突を起こせる。hash を改良すると衝突しなくなるので、テストの前提として `hash(a) % cap === hash(b) % cap` も確かめる。put / remove は戻り値ではなく、実行後の `entries` / `get` / `size` を検証する (準備 → 実行 → 確認)。capacity が大きいときは、該当インデックスだけを比べる。エラーは `expect(() => ...).toThrow(TypeError)` で確かめる。
