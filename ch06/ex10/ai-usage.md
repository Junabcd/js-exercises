# AI 利用記録 (ch06/ex10)

- 用途: 配列にもスプレッド構文が使えるかの確認、解答をどう 2 行に分けるかの相談、テストタイトルの相談、オブジェクトリテラルの中に `{ }` を入れ子にしてよいかの確認。解答コードは AI に生成させず、ヒントと小さな例をもとに自力で書いた。

## 質問したプロンプトと得られた回答の要約

1. **「num と foo, bar, buzz あたりは簡略記法やスプレッドで書けるが、arr もそれでいける？そうすると 1 行くらいで書けそうだけど」**
   - いける。スプレッド構文 `...` は配列リテラルの中でも使える。問題とは別の変数を使った例 `[...a, x, ...b]` で、配列の要素を展開しつつ、間に普通の値も混ぜられることが示された。
   - 注意点 1: `arr` という名前の変数はないので、`arr` は簡略記法では書けず `arr: [...]` と書く必要がある。
   - 注意点 2: オブジェクトのスプレッドは、後から展開したほうが同名のプロパティを上書きする。`bar` と `buzz` が重なっているので、期待値 (`bar` は obj3、`buzz` は obj2) に合う展開順を考えるよう言われた。
   - `toEqual` はプロパティの並び順を見ないので、キーの順番は気にしなくてよい。

2. **「arr の行とそれ以外で 2 行でもいいかな？イメージとしては `{num1,num2,...obj1}` みたいなのと、`arr:[...]` で 2 行」**
   - その分け方で問題ない。
   - ただし `...obj1` だけでは足りないので、obj2 と obj3 も展開する必要があり、展開の順番に注意すること。順番を間違えてもエラーにはならずテストが失敗するだけなので、Vitest の差分表示でどのキーがずれているかを確認するとよい。
   - Prettier で整形すると、長い行は複数行に折り返されることがある。

3. **「これも test() を付けなきゃいけないと思うけど、どんなタイトルがいいかな」**
   - 日本語・英語のタイトル候補が示された。課題の主旨 (簡略記法とスプレッド演算子) がタイトルに入っているものがおすすめ。
   - 他のテストファイルと言語をそろえると読みやすいこと、`describe` で囲む書き方もあることを教わった。

4. **「`const answer = {}` の中に、また `{}` を使用して簡略記法とか書いていいんだよね？」**
   - よくない。外側の `{ }` がすでにオブジェクトリテラルなので、その中にはプロパティを直接並べる。中にさらに `{ }` を書くと SyntaxError になる。
   - `{ }` を入れ子にできるのは `key: { ... }` のようにプロパティの値として書く場合だけで、その場合はネストしたオブジェクトになるので obj と等価にはならない。
