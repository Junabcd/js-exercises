## 質問したプロンプトと得られた回答の要約

1. **「『オブジェクトリテラルで独自プロパティを持つオブジェクトを定義し』は、要は `let point = { x: 0, y: 0 };` みたいに作れってこと？」**
   - その理解で正しい。`{ ... }` で直接定義した `x`, `y` が独自プロパティ。`Object.create(point)` で作ったオブジェクトから見ると、それらは継承プロパティになる、という対比を確かめるための問題。

2. **「テストコードを書こうと思うけど、どんなテストをすればいい？」「自由に作ればいいんだろうけど、正直迷う」**
   - 観点は (1) `Object.getPrototypeOf` の結果が渡したオブジェクトと同じ、(2) 継承プロパティは読めるが独自には持っていない、(3) 余裕があればプロトタイプとのつながり (シャドーイング)。迷ったら問題文の要件だけを一番小さく作る。`console.log` で確かめていたことを `expect` に置き換えればテストになる。

3. **「`let point` を export とかはできないんだっけ？」**
   - できる。ただし再代入しないなら `const` が一般的。import 側からは再代入できないが、プロパティの書き換えはできる。

4. **「書き換えた値がほかのテストに残り、テストの順番で結果が変わる、ってどういうこと？」**
   - モジュールは最初の読み込み時に 1 回だけ評価され、import するたびに同じオブジェクトが渡される。あるテストで値を書き換えると、後のテストにも残る。単独で実行すると成功し、ほかのテストと一緒に実行すると失敗するので、原因を探しにくい。Vitest はテストファイルごとにモジュールを読み込み直すので、この問題は同じファイル内のテスト同士で起こる。

5. **「オブジェクトを作る関数って簡単に作れる？ function でオブジェクトを作って return すれば、呼ぶたびに評価されるからテストに影響しないってこと？」**
   - その理解で正しい。ただし、オブジェクトリテラルは関数の「中」に書く必要がある (外に書いて return すると毎回同じオブジェクトを返す)。アロー関数でオブジェクトを返すときは `() => ({ ... })` と ( ) で囲む。

6. **「`toStrictEqual` で比較すれば問題の意図に沿っているよね？」**
   - 沿っていない。問題は「渡したオブジェクトそのもの」かどうかを求めているので、参照の一致を見る `toBe` を使う。`toStrictEqual` は中身を比べるだけなので、中身が同じ別のオブジェクトでも成功してしまう。

7. **自作コードのレビュー (「ex02 の中身を見てそうなっているか確認して」)**
   - テストは通っていたが、意図どおりの確認になっていなかった。
     - `Object.getPrototypeOf(point)` と向きが逆で、`Object.prototype` と `newPoint` を比べていた。どちらも独自の列挙可能プロパティを持たないため、`toStrictEqual` では偶然成功していた。
     - `createNewPoint()` の中と、テストの中で `createPoint()` を別々に呼んでいるので、2 つの `point` は別のオブジェクト。向きを直して `toBe` にしても、今の構成では失敗する。
   - 修正方法のヒントとして、プロトタイプにするオブジェクトを引数で受け取るか、両方をまとめて return する方法を教わった。直したあと、わざと別のオブジェクトを渡してテストが失敗するかを確かめるとよい。

8. **「まとめて return すると、テストのとき受け取るのが面倒になる？」**
   - `return { parent, child }` と簡略記法で返し、`const { parent, child } = ...` と分割代入で受け取れば 1 行で済む。引数で受け取る方式の方が `Object.create(proto)` の形に近く、テストを読むだけで何を渡したかがわかるので素直、という比較も教わった。

9. **シャドーイング (「作ったオブジェクトに同じ名前のプロパティを代入したらってどうやるの？」「新しいプロパティを作るわけではなく？」「プロパティを指定して何か入れろってこと？」)**
   - `child.theme = "dark"` のように、プロトタイプにあるのと同じ名前を指定して値を代入するだけ。プロトタイプの値は書き換わらず、`child` 自身に新しく独自プロパティが作られ、プロトタイプのプロパティが隠される (シャドーイング)。名前は同じでも、別々のオブジェクトにある別々のプロパティ。代入の前後で `hasOwnProperty` の結果を比べると確かめられる。この確認は問題文の必須要件ではない。

10. **レビュー指摘を受けての修正**
    - `createNewPoint(point)` がプロトタイプにするオブジェクトを引数で受け取る方式に変更した。これでテストの中で作った `point` をそのまま `Object.create` に渡せる。
    - テストを `expect(Object.getPrototypeOf(newPoint)).toBe(point)` に直した (向きを修正し、`toStrictEqual` から `toBe` に変更)。
    - 観点 2・3 のテストを追加した。継承プロパティを読めるか、`Object.keys` で独自プロパティを持っていないか、プロトタイプ側の変更が反映されるか、作ったオブジェクトへの代入でプロトタイプが変わらないか (シャドーイング) を確かめている。各テストで `createPoint()` を呼び、テスト同士が影響しないようにした。
